# Opportunity Radar V2 关键词优先与深度 VOC 需求说明

## 背景

当前结果只对四个固定社区做一次有限列表采集，4,000 个候选帖子中只有 88 个通过证据门禁并进入 Codex 分析；随后又按社区分别归并，形成 49 个话题，其中 40 个是弱信号。因此报告看起来“话题很多、每个证据很少”，且部分叙述仍为英文。

## 目标

把数据链路改成“关键词优先、社区归因”：

1. 用柴油皮卡平台、部件、故障、使用场景和购买意图词在 Reddit 全站检索；
2. 保留四个种子社区作为定向基线，同时从全站结果自动发现并记录其他相关社区；
3. 对帖子、评论做去重、时间过滤、证据分级和分层深读；
4. 先提取场景—任务—痛点—需求—现有方案—方案缺口，再跨社区做语义话题归并；
5. 只把多用户、重复出现、有证据的主题放入主报告，弱信号单独展示；
6. 所有分析叙述使用中文，英文只保留原始证据和关键词；
7. 生成接近 WhatToSell 信息密度的中文报告，结论、统计和证据来自同一份 analysis.json。

## 范围

- 时间范围由网页/CLI选择，限制最近 365 天；本次验证先跑已有 365 天原始数据，再决定是否重新采集。
- 四个种子社区：r/Cummins、r/Duramax、r/powerstroke、r/FordDiesels。
- 全站关键词结果中的其他社区可以进入本次 observed 社区集合，但只有达到证据门槛才升级为正式候选，不自动污染长期批准库。
- 生产采集不设置候选帖子数、深读帖子数、关键词数或社区数上限。每个查询持续分页，直到越过开始日期、没有下一页、连续页面不再产生新帖子，或 Reddit 明确拒绝继续返回。
- 通过相关性清洗的去重帖子全部获取正文和评论树；评论及回复持续分页/展开到 Reddit 不再返回，不使用“前 100 条评论”作为业务口径。
- Reddit 搜索本身可能只返回其可检索结果，因此报告表述为“在所选时间窗口内可合规获取的 Reddit 样本”，不得宣称抓到了 Reddit 全量。
- 不生成用户主页画像，不生成排放删除等违规操作教程。

## 社区库和关键词库闭环

- library/keywords.json 保存种子词、历史激活词和每轮新发现词；以 normalized_term 为唯一键，重复发现只更新证据、作者数、社区数、首次/最近出现时间和运行 ID。
- library/communities.json 保存种子社区和每轮发现社区；以小写 subreddit 为唯一键，大小写差异不能生成重复社区。
- 每轮开始时读取两个库的 active 项并写入不可变 config snapshot，确保“已收录”不仅存在于表格中，而且实际参与本轮检索。
- 每轮采集和 VOC 完成后自动 upsert 新词与新社区。所有有效发现至少进入 observed；达到证据门槛自动进入 active，并在同一轮增量检索中使用，不等待人工审批。
- 关键词自动激活门槛：至少 2 篇不同帖子、2 名不同作者，且柴油相关性通过；或来自 1 条高质量直接体验证据并包含具体部件/车型/故障组合。
- 社区自动激活门槛：至少 3 篇相关帖子、3 名作者；或被 2 个不同关键词组命中且至少有 2 篇直接体验帖子。
- 每轮 manifest 和 Excel 分别列出 loaded、observed、activated、used、rejected 数量，并保存 source_post_ids、source_comment_ids 和 source_queries，确保可检查、可追溯。

## 成功标准

- 全站关键词检索与四社区定向检索均可运行并按帖子 ID 去重；
- 在时间窗口内持续分页和深读，不存在业务数量上限；停止必须有日期边界、无下一页、无新 ID 或外部拒绝等可记录原因；
- 运行记录实际覆盖日期、来源查询、社区发现和失败原因；
- 所有发现词和社区均完成唯一键 upsert；active 项必须出现在下一轮 config snapshot 和 used 查询记录中；
- 主报告默认只显示正式主题，弱信号折叠显示；
- 正式主题至少有 4 篇帖子/3 名作者，或 3 篇帖子跨 2 个社区，或 3 篇帖子且 8 名独立讨论参与者；
- 每个主主题都有中文的场景、用户任务、痛点、需求、当前方案、方案不足、机会假设、反方观点和验证问题；
- 每个结论可回链到至少一条 Reddit 帖子或评论证据；
- HTML、Excel、JSON 的核心数字一致。
