## 2. 报告格式结构（8 个 tab）

### 2.1 卖家报告（overview）— 默认首页
- **Hero 区**：品类 eyebrow + 大标题 + 执行摘要 + Seller Verdict（金色竖线强调）
- **5 个指标卡**：帖子 / 评论 / 合格证据 / 候选信号 / 失败记录
- **右侧研究边界卡**：国家、地理规则、分析引擎、运行状态、persona_status、隐私说明
- **正式机会区**：分数环（72px 圆形）+ 标题 + 机会类型标签 + 痛点 chips + 事实/推断/未知分栏 + 价格带/制造/物流/退货风险 + 代表证据（可展开）
- **候选信号区**：与正式机会同卡片样式，标注"尚未达到门槛：xxx"
- **研究范围区**：正式词/探索词/扩展词 + **失败记录（可折叠 `<details>`）**
- **未知项区**：跨机会汇总的 unknowns

### 2.2 Audience Map（map）
- 三栏布局：左侧筛选（搜索框 + 分类按钮 + 重置）| 中图 SVG 二部图 | 右侧详情面板
- 图形：产品节点（绿圆，半径按机会分）+ 社区节点（白圆，按帖数）+ 连线
- 交互：点节点 → 右侧显示机会/痛点/代表证据；搜索/分类实时 dim
- 空数据：显示"暂无机会或社区数据"提示

### 2.3 关键词词云（keyword-cloud）
- 三栏：左侧筛选（搜索 + 类别 + 状态 + 最低分数滑块 + 重置）| 词云区 | 右侧详情
- 词云：按钮式词条，font-size 按 display_weight（14-42px）
- 交互：点词 → 右侧显示状态/来源用户/社区/父级种子词/代表证据

### 2.4 痛点（pain）
- 双栏卡片：痛点标题 + 证据数/社区 + 关联正式机会 + 关联解决方向 + 代表证据（可展开）

### 2.5 竞品/现有产品（competitors）
- 双栏：竞品卡（品牌信号）| 现有产品卡（未命名产品按标题）

### 2.6 邻近配套（adjacent）
- 与正式机会同卡样式，标注 adjacent_bundle 类型

### 2.7 用户画像（personas）
- 样本不足时：显示缺口列表（qualified_evidence/qualified_users/deep_dive_authors 实际 vs 目标）
- 样本足时：画像卡 + 自述聚合（年龄/州/预算，仅聚合不落个人）

### 2.8 证据库（evidence）
- 搜索框 + 合格/排除计数 + 证据卡网格（社区/类型/质量带/地理 + 英文原文引用 + 原文链接）

## 3. 已定格式规范（新改动必须遵守）

1. **自包含**：无外部 CDN/字体/脚本依赖，`<script src>` 和 `<link href>` 禁止（测试断言）
2. **JSON 单一事实源**：页面数据全部内嵌 `<script type="application/json">`，JS 读取渲染
3. **hash 深链**：`report.html#map` / `#keyword-cloud` / `#pain` / `#competitors` / `#adjacent` / `#personas` / `#evidence` 直达对应 tab（已实现，新增 tab 需同步）
4. **失败记录折叠**：`<details class="failures-detail">`，有 N 条默认收起、0 条默认展开
5. **空态提示**：地图/词云/证据无数据时必须显示中文提示，不留空白
6. **证据链接**：必须是 `https://www.reddit.com/r/<sub>/comments/<id>/` 完整格式（短链会 404）
7. **中文术语**：界面用中文（卖家报告/Audience Map 保留英文品牌名）；禁止英文术语混排（如 GPM）
8. **行尾符**：文件内容用 LF；不要引入 CRLF 噪音（worktree 曾被污染，`git diff --ignore-space-at-eol` 为空才算干净）
