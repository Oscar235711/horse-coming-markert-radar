# 研究问题驱动的使用方式

Opportunity Radar 的网页入口不是关键词管理器。用户只需要描述想了解的柴油皮卡改装问题，系统负责把问题转成英文检索概念、搜索全站 Reddit、发现相关社区，并将有效证据沉淀回库。

## 一次运行

1. 打开 `radar serve` 提供的本地网页。
2. 在“你想了解什么？”输入自然语言问题，例如：`我想了解 Duramax 拖挂时的高温和排气改装痛点`。
3. 选择时间范围和采集深度，点击开始。
4. 任务先调用 DeepSeek（Higress 网关）生成检索计划，再由 OpenCLI + Chrome 获取帖子、评论和回复。
5. 任务完成后下载 `analysis.json`、HTML 和 Excel。

## 系统如何用库

- 社区库保存四个柴油种子社区以及后续发现的相关 subreddit。种子社区是后台基线，不是用户必须选择的范围。
- 关键词库保存平台、部件、故障、场景、购买意图和社区黑话。用户问题和本轮扩展词优先使用；历史库只使用通过语义清洗的有效概念。
- 话题库保存经过 VOC 分析的用户任务/问题，不等同于检索关键词。

`just got`、`because im`、`all the time` 等语法碎片会进入隔离区，不会作为检索词，也不会出现在用户首页。

## 结果关系

```text
研究问题
  → 检索计划与扩展词
  → 全站帖子/评论证据
  → 相关社区归因
  → 用户场景—任务—痛点—需求—方案缺口
  → 社区 → 话题 → 证据报告
```

报告中的社区只展示本轮实际命中且满足相关性门槛的社区；没有证据的种子社区不会被强行画出来。所有产品方向均为机会假设，不替代业务、工程和合规判断。
